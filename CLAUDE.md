# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

"地主与农民" (Landlord and Farmer) is a real-time multiplayer "bankruptcy race" betting game. Players take asymmetric roles — Landlord (1) vs Farmers (1-4) — and each round secretly bet money cards, a coin flip decides the winner (heads = landlord, tails = farmers), then money is settled/negotiated. A player is bankrupt at balance ≤ 0; the game ends when the landlord or all farmers go bankrupt.

**The authoritative design document is `docs/GAME_SPEC.md`** — all rules, parameters, protocol, and architecture decisions live there. Update the spec first, then the code.

## Commands

Run from the repo root (npm workspaces: `server`, `client`).

- `npm run dev` — server (`node --watch index.js`, port 3001) + client (Vite, port 5173) concurrently
- `npm run build` — builds the client
- `npm run lint` — run from `client/`: `cd client && npx eslint .`
- No test suite. The pure logic in `server/logic/` is designed to be unit-testable with plain `node -e` scripts.

Vite proxies `/api` and `/ws` to `http://localhost:3001` (`client/vite.config.js`). The WS path is `/ws` with `?token=` auth.

**Offline visual verification**: `client/preview.html` + `src/preview.jsx` mount the real `GameScreen` with mock zustand state and no backend — with `npm run dev` running, open `/preview.html?phase=LOBBY|DISCUSSION|BETTING|FLIGHT|REVEAL|COIN_FLIP|SETTLE|NEGOTIATE|FINALIZE|ENDED`. Useful for screenshot-checking 3D scene/UI changes. `preview.html` is a second HTML file in `client/` but isn't a Vite build entry, so it's excluded from `npm run build`.

**Visual verification gallery** (preferred for presentation-layer changes): `client/preview/gallery.html` (+ `gallery.jsx`, `README.md`) — a scene-switcher harness that mounts real components with mock state so UI/art/animation changes can be eyeballed without launching a game. Open `/preview/gallery.html`. Add a scene by appending to the `SCENES` array (`kind:'game'` mounts `GameScreen` with a mock `viewFor` state; `kind:'grid'` renders prop-driven components directly). Also excluded from the build.

## Architecture principles (do not violate)

1. **Server-authoritative**: all rules/settlement/validation run on the server; the client only renders `state` and sends intents. The client must never compute balances or outcomes.
2. **No hardcoded parameters**: every tunable number lives in `server/config.js` (`DEFAULT_CONFIG`), overridable per room at creation. `getInitialBalance`/`getMinStake` are the reserved extension points for player-count-dynamic values.
3. **Logic/presentation split**: `server/logic/` is pure functions (no IO); `Room.js` owns the state machine. Client `scene/` (real 3D via react-three-fiber) and `ui/` (2D HUD) layers only read the zustand store — no game logic or balance/outcome computation in components.
4. **Data lives server-side**: accounts and game records persist via `server/storage.js` into `server/data/` (gitignored JSON; swap point for a real DB). Client localStorage holds only the auth token.
5. **Art via registry, with shared canvas assets**: components get art through `client/src/assets/registry.jsx` `getArt(key)` — the single swap point. Icons/coin badges are SVG (`assets/svg/index.jsx`). Money notes are canvas-rendered by `assets/pixelnote.js` (`PixelMoneyNote`), and that *same canvas* is reused as a `THREE.CanvasTexture` for the 3D table cards (`scene/textures.js`'s `noteTexture`) — hand and table cards are guaranteed visually identical. All HUD digits/Latin text render through the hand-authored bitmap font in `assets/pixelfont/`; Chinese text falls back to a CJK pixel-font CSS stack (`--font-cjk` in `pixel.css`).

## Server (`server/`, ESM)

- `config.js` — `DEFAULT_CONFIG` (all parameters: farmer initial 8 + `landlordFundMultiplier` 1.2 so landlord = ⌊1.2 × total farmer funds⌋, min stakes, settlement multipliers/rounding/debt allocation — `landlordWinMultiplier` 1.5 so landlord-win target = ⌊1.5 × bet⌋, `landlordGoal` explicit checkpoint `schedule` (interval/multiplier pairs), phase timings, reconnect grace…), `mergeConfig`, `getInitialBalance` (landlord now player-count-dynamic), `getMinStake`. **Tunable params are documented in `docs/TUNING.md`.**
- `logic/landlordGoal.js` — landlord funds-goal checkpoint schedule + penalty (pure; see GAME_SPEC §3.7). Tests: `node server/test/logic.test.mjs` (pure boundary tests) and `node server/test/payout.test.mjs` (real Room phase-machine integration with tiny timings: take gate, timeouts, offline auto-take, competitive adjust steps).
- `modes/index.js` — mode registry: `quick` and `competitive` (role-skill system, §8) available; `classic` (bank role) registered but `available: false`.
- `logic/apportion.js` — largest-remainder integer apportionment (all splits go through this; per-person error ≤ 1).
- `logic/rules.js` — `flipCoin`, `betBounds`/`validateBet` (bet ∈ [minStake, balance−minStake]; forced all-in when balance < 2×minStake), `allocateDebt` (capacity-capped recursive re-apportionment, default `inverseBet` = "whoever bet more covers less"), `settleRound` (default payout plan), `applyAllocation` (final booking math incl. per-farmer `paidBy`; bankruptcy list).
- `logic/payout.js` — **table-explicit settlement (GAME_SPEC §3.8)**: `buildSettleScript` (gather/split choreography steps), `createLedger` (tracks each player's on-table pile vs hand debits; invariant `pile = after − (balanceNow − handDebit)`), `flowsFromParts`. Every FINALIZE money movement (debt collect, goal penalty, wage, meal allowance, capitalist pool/tax) emits a generic `adjust` step `{source, label, flows:[{from:{kind,id},to:{kind,id},amount}]}` with `kind ∈ pile|hand|pool|void` — **adding a new mechanic = push one more adjust step server-side; the client animates it with zero changes** (unknown `source` falls back to the server-sent `label`).
- `auth.js` — register/login (scrypt+salt), token sessions, duplicate login kicks the old socket, online presence.
- `storage.js` — JSON persistence (`users.json`, `records/*.json` per finished game).
- `Room.js` — phase machine: `LOBBY → DISCUSSION(ready) → BETTING → REVEAL(confirm) → COIN_FLIP → SETTLE → NEGOTIATE → FINALIZE → DISCUSSION(next round) | ENDED`. The four payout sub-phases are SETTLE (system plan + gather/split script) / NEGOTIATE (farmers drag money & debt between each other; any change resets confirmations; skipped if ≤1 farmer or nothing to split) / FINALIZE (collect/adjust steps + **take gate**, then history/bankruptcy) / next DISCUSSION. **Deferred booking (§3.8)**: hand-side debits book at FINALIZE entry; each player's on-table pile books only when they send `take_payout` (F key); bankruptcy flags + round end fire after all eligible players have taken (`timing.takeAutoDelayMs` auto-takes offline/spectator players, `timing.takeTimeoutMs` backstops AFK, `_endGame` books leftovers so money is never lost). `Room.payout = {script, piles, taken, eligible, deadline}` goes out via `viewFor().payout`; during NEGOTIATE the landlord sees `piles` **frozen at the system plan** (negotiation stays farmer-private) and his client reconciles at FINALIZE. Offline players are auto-acted (`autoActForOffline`) so gates never stall. `viewFor(playerId)` is the **privacy boundary**: others' balances `null`, bet amounts hidden during BETTING (`hasBet` only), `allocation` visible to farmers/spectators only, `history[].balancesAfter` stripped unless spectator/ENDED.
- `index.js` — thin REST (`/api/auth/*`, `/api/online`, `/api/modes`, `/api/rooms`) + WS dispatch. Single `state` push pattern: every mutation broadcasts each player their own `viewFor` view; client animations are driven by state diffs, not bespoke events. `voice_*` message types are reserved (reply `NOT_IMPLEMENTED`).

## Client (`client/src/`, React 19 + Vite + zustand + three/@react-three/fiber/@react-three/drei)

- `store/authStore.js` (token/login, localStorage). `store/gameStore.js` — mirrors server `state`/`chat`/`toast`/`kicked` (never computed client-side), plus transient presentation state: `chatOpen` (also suppresses game keyboard shortcuts), `insuranceDrops`, and `betFlight`/`myStack` + `startBetFlight`/`finalizeBetFlight` — the bet-flight handoff: the exact card models that fly from hand to table become `myStack` once the flight ends, so nothing swaps; `placeTableStack` is the 3D-input variant (cards already dragged onto the table become `myStack` with no flight). `net/socket.js` — WS singleton with auto-reconnect and rejoin (handlers injected by gameStore to avoid import cycles). `api.js` — REST with Bearer token; 401 clears the session.
- **Input modes** (`game/inputMode.js`): `IS_3D_INPUT` — default `'3d'` = direct table manipulation (HandLayer bet dragging, PayoutLayer negotiate dragging); `?input=2d` restores the legacy 2D HUD interactions (`MoneyHand`/`NegotiationBoard`), which are **kept, not deleted** (future mobile). Server protocol is identical in both modes.
- `App.jsx` routing: no token → `LoginScreen`; no room → `LobbyScreen` (mode cards, room list, join by id); else `GameScreen` (composes `scene/Scene3D` + `ui/UiLayer` + `ui/McChat` + `ui/InsuranceDropLayer`).
- `scene/` — **3D scene layer** (react-three-fiber, presentation-only, reads the store):
  - `cards.jsx` — shared table-money primitives (Scene3D and PayoutLayer must stay visually identical): `cardMaterials(value, debt)` builds one 6-face material array per denomination (`+y` = face texture via `noteTexture`, `-y` = back texture, edges = denomination accent; `debt` = red variant) — face-up/down is purely `rotation.x` (0 vs π), never a material swap. `cardLocal(i)`/`cardYaw(i)` give each card's slot in a stack, shared by static piles and every flight landing point. `MoneyStack` (static pile + optional `¥n` label), `ArcNote` (generic world→world quadratic-Bezier note flight with grow-in/shrink-out, the settlement choreography's brushstroke).
  - `Scene3D.jsx` — `<Canvas>` containing `Table` (3D mesh, felt-baked betting circles), opponent `MinecraftPlayer`s seated per `SEATS` layout, `MoneyStack`s, `Coin`, and `CameraRig` (damped mouse-look, not free-fly). `FlyingNotes`/`FlyingNote` animate a bet: each selected hand card's on-screen rect is unprojected to a 3D world point, then flown along a quadratic-Bezier arc to its exact `MoneyStack` slot — same mesh flies and lands, so there's no handoff pop (2D mode + the 3D forced-all-in path both use this). During payout phases the per-player bet stacks yield to `PayoutLayer`. Mounts `HandLayer` during BETTING (3D input mode). `Projector` publishes a 3D→screen projector via `scene/projection.js`.
  - `HandLayer.jsx` — **3D hand (BETTING, 3D input mode)**: balance decomposed into real card meshes fanned in a camera-attached group (looks up → hand tucks away via `look.y`); drag a card (gravity-gun spring follow, `carry.js`) into your felt circle to stage a bet — staged cards use the exact `cardLocal/cardYaw` slots so `placeTableStack` hands them to Scene3D with zero pop; click a staged card to reclaim it (arc flight back to hand); long-press splits (same 450/140ms as MoneyHand); min-stake reserve sits face-up outside the circle (non-interactive); investors get a pledge ring left of the circle; all prompts are white background-less `PixelText` floats over the circle (`.felt-float`), confirm = Enter or clicking the float. Forced all-in confirms via the legacy `startBetFlight` pipeline.
  - `carry.js` — shared gravity-gun helpers: `groundFromPointer` (pointer ray ∩ table plane, clamped to felt) + `CarrySpring` (under-damped spring follow + velocity tilt). Used by HandLayer and PayoutLayer's negotiate drag. **Three hard-won rules for the press-drag-split gesture** (both layers): ① the `pressActiveRef` (real button held) is tracked with a window `pointerdown` listener registered in the **capture phase** — r3f's canvas raycast handler fires in the bubble phase, so a bubble-phase flag would still be false when the mesh's `onPointerDown` runs and the drag would never start; ② the long-press split timer's callback re-checks `pressActiveRef` so a raycast that lags past mouse-up (SwiftShader) can't fire a spurious split; ③ pointer listeners are registered **once** (stable effect deps) and read live seat/spot data from a ref — depending on `players`/`spots` re-runs the effect on every WS broadcast, and its cleanup would abort an in-progress drag/split.
  - `PayoutLayer.jsx` — **table-explicit settlement director (§3.8, presentation-only)**: owns a mutable table model (piles/debt markers/pot/flights) in a `Director` class; plays unseen `payout.script` steps sequentially (gather → pot, redeal-split toward each recipient, deliver into felt circles, generic `adjust` flows — no floating ±N numbers, amounts show on the pile labels; details live in the FINALIZE panel/ledger), then **reconciles** local piles against authoritative `payout.piles` (diff → flights) — the same mechanism mirrors others' NEGOTIATE transfers live and catches the landlord up at FINALIZE. **NEGOTIATE 3D drag**: round farmers grab notes off their own pile/debt pile (`MoneyStack onNoteDown` → gravity-gun carry), drop on a teammate's circle → `negotiate_transfer` + optimistic update of both the local model *and* `latestPiles/latestDebts` (so the server echo reconciles to zero); `dir.holds` (a **refcount**, not a boolean — rapid consecutive drags must not let the first landing unfreeze the second) freezes the queue/reconcile while any card is airborne in a player's grip or in-flight; long-press splits pile notes locally (reconcile only compares amounts, composition is free). On phase-out mid-drag the effect cleanup lands any carried note back and decrements `holds` so FINALIZE never freezes. Takes: own pile flies to the balance candle (screen-point unprojection), others' piles absorb into their bodies; own pile shows a background-less `拿取 [F]` text float (same style as the `¥n` pile label). **Two hard-won rules**: all scheduling runs on the render-frame clock (`DirectorClock`), never `setTimeout` — and a step only advances when its estimated time is up **and all spawned flights have landed and nothing is held** (`_advance`), otherwise low-FPS machines double-land money. Cold mounts (reconnect/gallery) snap to the final layout without replaying. New adjust `source`s animate generically.
  - `MinecraftPlayer.jsx` — Minecraft-style box-stacked character (head/body/arms/legs, idle bob + arm-swing via `useFrame`), role-colored (landlord = gold crown, farmer = green; bankrupt = grayscale + tilted), expression baked into the head's front-face texture (`textures.js#faceTexture`). Overhead nameplate via drei `<Html>` billboard: Minecraft-style plain `<PixelText>` player name only — no backing panel, no role/bankrupt tags (role reads from the head prop, bankrupt from the gray tilted body).
  - `Coin.jsx` + `coinSim.js` — pixel coin (low-poly cylinder + NearestFilter textures). `coinSim.js` pre-bakes deterministic **two-regime planar physics** offline: ① ballistic tumbling — gravity fall + fast flip-axis spin + restitution bounces against an edge-aware floor `tableTop + R·|sinθ| + H·|cosθ|` (prevents table clipping); ② once vertical energy is spent the coin's edge stays on the table and it does a **planar damped rock** (gravity restoring torque toward the nearest flat face + per-slap energy loss → a few tip-flat-tip cycles, then lies flat). This is the natural settle of a *flipped* coin — deliberately **not** an Euler's-disk rim-precession (no `rz` wobble). Trajectories are bucketed into pools of `POOL_SIZE` (24) heads / tails by their *natural* landing face and cached. **Fairness-of-perception design** (the result is already a server-side 50/50 — the goal is to make the animation *look* fair): the start face is randomized 50/50 (no opening tell), spin is fast enough that the tumbling face is an un-trackable blur (suspense / feels random), flight params are drawn blind and bucketed by outcome so the flight never telegraphs the result, and `pickFlip` layers a per-replay yaw + horizontal mirror (both face-preserving) so the same baked clip never looks repeated. `mode="flip"` picks a random baked trajectory matching the server-authoritative `coinResult` and replays it (frame-interpolated, applying that yaw/mirror); `mode="rest"` shows the final face flat.
  - `textures.js` — `THREE.CanvasTexture` generators, all `NearestFilter` for crisp pixels: `faceTexture` (player expressions), `coinFaceTexture` (王/禾), `noteTexture` (delegates to `assets/pixelnote.js` so 2D and 3D banknotes share one canvas).
  - `projection.js` — module-level singleton (`setProjector`/`projectPoint`): lets 2D UI code query where a 3D world point lands on screen without prop-drilling the camera.
- `ui/` — **2D HUD layer** (pointer-transparent except interactive elements):
  - `UiLayer.jsx` — top bar (room id/round/phase chip + exit), role/mechanic HUD column top-left under the room chip (`.hud-left-stack`: GoalHud/CapitalistHud/WageHud/GluttonHud, black-translucent `.goal-hud.hud-card` skin), right-side vertical `PlayerRail`, bottom-right `BalanceHud` (own balance in large `PixelText`), phase hint, the current phase's action panel (in 3D input mode BETTING/NEGOTIATE panels render nothing for actors — interaction lives on the table; FINALIZE has no take button, only the F-key/table prompt), and global keyboard shortcuts (`useGameKeys`: `T` opens chat, `F` takes the payout pile during FINALIZE, Enter/Space does the context action, all suppressed while typing or `chatOpen`).
  - `MoneyHand.jsx` — **2D legacy** (mounted only with `?input=2d`): balance decomposed into 10/5/2/1 notes via `game/notes.js`, reserved min-stake shown locked aside. Click selects; long-press (450ms, shake starts at 140ms via `.hand-note.shaking`) splits a note. On confirm, the selected cards' screen rects are captured and passed to `gameStore.startBetFlight`, then `place_bet` is sent.
  - `NegotiationBoard.jsx` — **2D legacy** (`?input=2d`): HTML5 drag of take/debt notes between farmer columns.
  - `McChat.jsx` — bottom-left Minecraft-style chat: idle messages fade after ~10s, `T` opens a scrollable input (Esc closes), farmers get a public/密谈 channel toggle. (The old 2D `FlightLayer` FINALIZE recovery ghost is retired — payout money flies in 3D via `PayoutLayer`.)
- `game/notes.js` — pure note decomposition/split helpers (presentation-only; the server only ever sees integer amounts). `game/payoutText.js` — adjust-step `source` → label text map (currently unused after the floating ±N labels were removed; kept for future textual surfaces).
- `assets/registry.jsx` — `getArt(key)`: `moneyNote` → `PixelMoneyNote` (canvas, shared with 3D), `coin` → `CoinFace` (SVG, login-screen badge), `icon` → `Icon` (SVG, used throughout the HUD); `avatar`/`tableSurface` (`CubeAvatar`/`TableSurface`) are registered but unused now that players/table render in 3D.
- `assets/pixelnote.js` + `PixelMoneyNote.jsx` — the canonical banknote visual: `draw(ctx, {value, faceDown, debt, locked})` paints a low-res pixel grid (per-denomination color table, debt = red, face-down "地" back design) onto a cached canvas; `noteCanvas`/`noteDataUrl` feed the 2D `<img>`, and `scene/textures.js#noteTexture` wraps the same canvas as a 3D texture.
- `assets/pixelfont/` — hand-authored 5×7 bitmap font (built for this project; an earlier `@fontsource/press-start-2p` dependency is unused): `glyphs.js` has point data for digits/A-Z/a-z/punctuation/¥$; `PixelText.jsx` splits text into ASCII runs (rendered as crisp inline SVG bitmaps) and non-ASCII chunks (rendered via the `.pixel-cjk` CSS class, which falls back to a CJK pixel font stack).
- `pixel.css` — hardcore Minecraft/pixel theme, loaded after `theme.css`/`App.css` in `main.jsx`: stone-panel borders/bevels, HUD layout (`hud-top`, `player-rail`, `balance-hud`, `mc-chat*`), note-shake keyframes, the 3D canvas container (`.r3f-scene`), nameplate styling.
- `assets/svg/index.jsx` — `CoinFace`, `CubeAvatar`, `TableSurface`, `Icon` (its `MoneyNote` export is dead, superseded by `PixelMoneyNote`). All colors via `theme.css` CSS variables (dark theme, white UI, gold accents).

## Adding a new WebSocket message type

1. Server: add a `case` in `index.js`'s switch dispatching to a `Room` method; the method should `_broadcastState()` after mutating.
2. If it changes what a player may see, expose it through `viewFor()` per-player (never raw global state).
3. Client: send via `useGameStore.getState().send({type, ...})`; render from the updated `state` (avoid bespoke client events — drive animations from state diffs).
