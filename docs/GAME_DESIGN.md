# 游戏设计文档（GAME_DESIGN）

> **定位**：本文是「设计叙述」——讲清楚这游戏*是什么、为什么这么设计、玩家在体验什么*。
> **权威数值与协议**仍以 [`GAME_SPEC.md`](./GAME_SPEC.md) 与 [`TUNING.md`](./TUNING.md) 为准；本文不覆盖规则，凡涉及具体数字均标注「默认值」并以 `server/config.js` 为最终事实。
> 当前已实现到什么程度见 [`IMPLEMENTED.md`](./IMPLEMENTED.md)。

---

## 1. 一句话概念

> **「地主与农民」是一场实时多人的「破产竞速」下注博弈**：玩家分属不对称的两个阵营——地主（1 人）对农民（1–4 人）——每回合各自**暗下注**，一枚硬币决定胜负（正面=地主赢，反面=农民赢），赢的一方按规则瓜分赌注，输的一方分摊亏空。谁先把对手（地主本人 / 全部农民）逼到余额 ≤ 0，谁就赢下整局。

核心张力不在「猜硬币」（硬币是服务端公正的 50/50），而在**下多少、跟谁结盟、怎么分账、怎么把风险甩给队友**——是一场披着赌局外衣的心理与谈判游戏。

---

## 2. 核心循环（一个回合）

```
讨论 DISCUSSION ──► 暗下注 BETTING ──► 亮注 REVEAL ──► 抛币 COIN_FLIP
   ▲                                                          │
   │                                                          ▼
下一回合 ◄── 正式结算 FINALIZE ◄── 农民协商 NEGOTIATE ◄── 系统结算 SETTLE
```

1. **讨论**：玩家就绪；可公开喊话或（农民阵营）走「密谈」频道串供。
2. **暗下注**：每人秘密押一笔钱（受最小出资额 / 余额上限约束）。别人只看得到「你下没下、下了几张牌」，**看不到金额**。
3. **亮注**：翻开所有人的注，等全员确认。
4. **抛币**：正面地主赢、反面农民赢。结果服务端先定，动画只负责把「公正」演得有悬念。
5. **系统结算**：服务端给出一份默认的分钱 / 分债方案。
6. **农民协商**（多农民时）：农民之间拖动「该拿的钱」和「该背的债」，互相腾挪——任何改动都会重置确认，逼出博弈。
7. **正式结算**：落账、记历史、判破产。
8. 回到讨论，进入下一回合，直到一方阵营出局。

**胜负**：余额 ≤ 0 即破产（默认阈值 0）。地主破产 → 农民胜；全部农民破产 → 地主胜。关键角色掉线/退出也会判定对应阵营胜。

---

## 3. 不对称是设计的灵魂

地主以一敌多：他的资金更厚（默认 = 农民总资金 ×1.2，竞技 ×2），但要**同时**赢过所有农民才安全，且背着「资金目标考核」的紧箍咒。农民人少则势单，人多则每人风险摊薄、但分账更难谈拢。这种「一个胖子 vs 一群瘦子」的结构，制造了天然的「以多欺少 / 以一镇多」拉锯。

**地主资金目标**（紧箍咒）：每过若干回合，地主必须达到一个递增的资金线，否则在该回合被扣一笔沉没惩罚（默认 `max(2, ⌊余额×0.2⌋)`，可扣到破产）。目标点由 `landlordGoal.schedule` 显式给出，逼地主不能只龟缩、必须主动赢钱。

## 4. 模式

| 模式 | 状态 | 角色 | 设计意图 |
|---|---|---|---|
| **快速** quick | 已开放 | 地主 / 农民 | 最纯粹的下注对决，破产竞速。无角色技能，适合快速上手。 |
| **竞技** competitive | 已开放 | 地主 / 资本家 / 基础农民 / 投资人 / 暴食者 | 角色技能制：两侧各有专属技能，把「下注」升级成「带 build 的下注」。 |
| **经典** classic | 未开放（开发中） | 地主 / 农民 / 银行 | 在快速基础上加入「银行」角色：放贷、利息、赦免。仅占位。 |

模式只决定「这局开放哪些角色、用哪套数值、有没有额外阶段」；回合机本身是共用的。

## 5. 竞技模式：五个角色，两个阵营

**阵营是核心抽象**——结算/胜负只认「哪一侧」，具体角色只改变你*怎么*影响这一侧的盈亏。

- **地主阵营**（恰 1 人，二选一）：`地主` / `资本家`
- **农民阵营**（1–4 人，可重复）：`基础农民` / `投资人` / `暴食者`

### 地主阵营

**🎩 地主 landlord** — 高风险高回报的支柱。资金最厚（默认 = 农民总资金 ×2），但背着资金目标考核。玩法幻想：用厚资本碾压，但不能松懈。

**🏦 资本家 capitalist** — 「钱生钱」的体系局。两套钱包：
- **个人资金**（押注钱包，**动态**）：每回合 = 6×农民数 + round(当前池÷10)，随池涨跌（开局 = 8×农民数）。**本金必归还、不决定破产**——押多少都不会直接押死自己。藏池让农民猜不准你的下注上限 L，是资本家「读牌/骗押」技巧的地基。
- **资金池**（血条）：默认 = 活跃农民数 ×20。**真正承接盈亏、每「农民人数」回合被抽税（当前池 ×10%、至少 2），耗尽即破产**。
玩法幻想：本金安全地反复豪赌，但资金池在周期性失血——你在和「税」赛跑（人越多、征税越疏）。

### 农民阵营

**👨‍🌾 基础农民 farmer** — 没有主动技能，靠**工资滚雪球**。每隔若干回合自动领一笔工资。规模效应：农民越多，发得越频、每次越多。
- 默认发薪间隔 `interval = max(2, 5 − (m−1))`，金额 `amount = 1 + (m−1)`，`m` = 当前活跃农民总数。
- 即：1 农民 = 每 5 回合领 1；每多 1 个农民，间隔 −1（最低 2）、金额 +1。人多则雪球滚得快，是农民「以多取胜」的根基。

**📈 投资人 investor** — 用「投保」对冲风险。下注时把手牌拖进投保槽投保 n（默认上限 3），**保费先扣**；若该回合农民输，则本阵营要分摊的亏空**减少 2n**（默认 `waiveMultiplier=2`）。玩法幻想：花小钱买保险，输了帮全队减负——团队型角色。

**🍖 暴食者 glutton** — 用「饭账」和「重掷」赌运气。
- **饭账**：每回合累积 +1 的**成本**（不是收益）。**仅当农民这边赢**时，把累积的饭账从他余额里**扣掉并清零**（可扣到破产）；农民输则饭账继续累积、不结算。寓意：能吃但要还账，赢了才结账。
- **重掷**：农民输（开出地主面）时，暴食者可重掷硬币，**每局次数 = 农民阵营人数**（每回合最多申请 1 次）。给农民阵营一个翻盘骰子——人越多、骰子越多。

> ⚠️ 设计修正记录：早期把「饭账」做成了「胜时发放的收益」，已纠正为「胜时扣除的成本」。详见 [`IMPLEMENTED.md`](./IMPLEMENTED.md) 的差异记录。

## 6. 结算与分账：把博弈做进规则里

- **地主胜**：目标 = `⌊地主下注 × 贪婪⌋`（默认 1.5）。pot 超出目标的部分，地主再按 **抽成**（默认 0.5）多拿一份；其余按规则回流。桌面不足目标时，缺口**再乘一次盘剥倍率**由农民用余额补足（三属性 greed/squeeze/rake 按地主侧角色区分，见 GAME_SPEC §3.5）。
- **农民胜**：农民平分 pot（默认 `equal`）。
- **分债（关键博弈点）**：默认策略 `inverseBet`——「谁下得多，谁分摊的债少」，且按各自承受能力上限递归再分配（largest-remainder 整数分摊，人均误差 ≤ 1）。
- **农民协商阶段**：系统给的只是*默认*方案。多农民时，农民可以互相拖动「该拿的钱 / 该背的债」，把账重新谈。这是把「队友之间的勾心斗角」显式做成了一个可操作的阶段。

所有分账都走整数分摊（`logic/apportion.js`），保证「分得干净、人均差不超过 1 块钱」。

## 7. 心理博弈层（这游戏真正好玩的地方）

1. **暗注**：你看不到别人押了多少，只看到「押了 / 几张牌」。要不要 all-in？对手的「张数」是虚张声势吗？
2. **抛币的「公正感」设计**：结果其实早已是服务端 50/50。动画的目标不是决定结果，而是**让它看起来公平又有悬念**——随机起始面（无开局暗示）、快到看不清的翻面模糊（像真的随机）、按结果分桶抽取的飞行轨迹（飞行过程不剧透结果）、每次回放叠加保面的偏航+镜像（同一段不会看腻）。
3. **协商**：赢了怎么分、输了谁背债，农民内部当场翻脸或抱团。
4. **密谈频道**：农民阵营有只有自己人（含破产观战者）能看的私聊频道，用来串供、分赃、甩锅；地主看不到。
5. **角色 build**：竞技模式下，「我是投资人帮全队兜底」还是「我是暴食者赌一把重掷」，让每个人的下注都带上了角色性格。

## 8. 体验与呈现基调

- **像素 / Minecraft 风**：方块角色、像素钞票、像素字体、低多边形硬币。轻松、复古、不严肃——冲淡「赌博」的沉重感。
- **3D 牌桌**：角色围坐，下注的钱牌真的从手上飞到桌面同一个位置落定（同一批模型既飞行也落桌，无切换突兀）。
- **服务端权威**：客户端只渲染服务端推来的状态、只发意图，从不自己算余额或胜负——保证多人之间绝对一致、无法作弊。

---

## 9. 设计原则（约束开发的护栏）

1. **服务端权威**：所有规则/结算/校验在服务端；客户端只渲染 `state` + 发意图。
2. **零硬编码参数**：每个可调数字都在 `server/config.js`，可按房间覆盖。
3. **逻辑/表现分离**：`server/logic/` 是纯函数；客户端 `scene/`+`ui/` 只读状态。
4. **阵营优先**：核心规则只关心阵营，角色只是「同一侧的不同技能皮肤」——便于加新角色。
5. **先改文档再改代码**：`GAME_SPEC.md` 是规则的唯一权威，改规则先改它。
