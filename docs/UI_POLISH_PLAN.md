# UI/交互打磨计划（基于 alpha 1.2，2026-07-04 玩家反馈 16 条）

> 总原则（反馈⑯）：**精简 HUD，把关键交互放到桌面上**——玩家的视线应该落在赌桌，而不是挤在
> 屏幕下方的一小块 2D 面板。凡是"桌上能表达的"，就用毡面浮字/桌面物件表达；凡是"低频信息"，
> 就收进设置面板或账本。逐阶段交付，每阶段做完先验收再进入下一阶段。

## 阶段一 · 手牌与拖拽手感（反馈①②③④⑬）

| # | 现状 | 目标 | 验收标准 |
|---|------|------|----------|
| ① | 手牌横排微弧、牌厚 0.05 互相穿模；悬停=整张上移+放大 | **扇面平行层**方案（第一版"滚转+错深"仍穿模，已打回重做）：所有牌严格平行于同一扇面、沿法线一张压一张（右牌在上）、绕腕部枢轴刚体张开——**平行层几何上不可能穿模**；手里的牌额外压薄（纯视觉）；悬停=沿这张牌自己的长轴**层内滑出一截**，遮挡关系不变（仍被右邻压着），才读作"抽牌"而非"抬起" | 满手牌（10+ 张）任意角度无穿模；悬停读作从手里抽出 |
| ② | 只能拖进圈 | 悬停任一手牌**短按点击**=直接飞入自己的下注圈（长按仍拆分、拖动仍拖拽）；**出牌一律反面朝上**（下注保密）：点击入圈顺势扣成反面，拖拽携带中即已是反面 | 点一下牌，弧线飞进圈内槽位反面落定；点圈内牌仍可收回 |

| ④ | look.y 过阈值→手牌整体二段式收起，生硬 | 类 Minecraft 持图手感：手牌组带**旋转滞后摆动**（甩视角牌跟着晃）；收放为连续量——抬头渐收进怀里，低头牌微微举近端详 | 甩鼠标有惯性摆；抬头/低头是平滑连续的收放 |
| ⑬ | 眼高 1.82 / 后退 0.62，自己的椅背入画 | 相机略高略远（1.98 / 0.82）；非自由视角**不渲染自己的椅子**（与不渲染自己身体一致） | 正常视角看不到自己的椅子；桌面与对家更完整 |

### 阶段三 · 任务风 HUD 图形化（二轮定稿，2026-07-05 用户给出完整设计，已落实）

一轮（大数字+蜡烛计点）被否——"劣质"；二轮按用户设计重做：**去标题行/大号数字/冗余文案**（"耗尽即破产""当前""未达罚"全删），每卡 = **图形 + 单行紧凑文案**（标签暗灰、数值按语义着色，全部 size 2；阶段名 size 3 是唯一大字）。

**阶段五 · 八轮修订（收起态淡出/滚动重构，已落实）**：四条反馈——①滚到上面再退出被强行拽到底再淡；
②悬停/收起只含**末 8** 快照，应改为「一屏放得下的**全部**消息」（长消息少、短消息多）；③滚轮查看范围
应是**整段近历史**而非 8 条；④可重构以求正确 + 性能。**重构要点**：
- **渲染全近历史**：不再 `slice(-8)`，收起态渲染 `accessible.slice(-100)`（COLLAPSED_CAP）——一屏放几条
  由框高（`max-height:220px`）与各行高**自然决定**，长消息占位多则放得少。展开态照旧按频道过滤全历史。
- **淡出改 DOM 直控**：`opacity`/`display` 由 **rAF 帧钟直写**各行 style，**不再触发 React 重渲染**（渲染只
  在消息到达/切模式时发生）——彻底消除逐帧重绘整列的性能隐患。故 `activeMs`/`born`/`hovering` 全部退出
  state、只留 ref。行 `ref` 内联回调写入 `lineEls` Map（其体在 commit 执行、不在 render，故不触发
  `react-hooks/refs`；渲染不频繁，抖动可忽略）。淡完 → `display:none` 收起、其余回流。
- **帧钟冻结 + 退出重发错峰租约**：`activeRef` 仅在「收起且未悬停」累加；展开/悬停冻结。悬停=冻结+`display`
  全开+`opacity=1`（满显整段近历史，含已淡完），滚轮**原地滚全段**（滚动条隐藏）；撤离 `GRACE_MS`=1.5s
  后恢复淡出、返回则取消。dt 上限 250ms 防后台掉帧暴冲。
- ⚠️**八轮首版曾误删 leaseFade（以为帧钟冻结可替代），是错的 → 九轮修回**：帧钟冻结只保留「剩余寿命」，
  而**退出聊天时展开态里的旧消息其寿命早已耗尽**（`remain≤0` → 一关就 `display:none` **瞬消**）、**展开时
  发的批量消息 `born` 相同**（会**齐淡**而非逐行）。故**退出/悬停撤离必须重发错峰满淡出租约**
  （`born_i = A + i·STAG + FADE_OUT_MS − life_i`，STAG=350，令此刻全 `opacity=1`、第 i 旧者延 `i·STAG` 才起淡）。
- ⚠️**九轮用固定「最近 12 条」又错 → 十轮改视野版 `leaseVisible`**：12 条会溢出 220px 框，最旧几条已滚出屏，
  却被纳入租约先淡 → 用户报「淡出不是从视野里的消息开始」；且悬停 reveal 已隐藏的旧消息会在上方撑高、
  把 `scrollTop` 拽到最早那条。**修法**：①`leaseVisible` 用 `getBoundingClientRect` 测**当前视野内**可见行，
  只对它们发错峰租约（最上/最旧先淡）、**视野外的立即 `born=A−life−1` 隐去**（否则可见者淡完后旧消息「回流
  上桌」重现）；②退出的 lease 延到收起布局落定（`useLayoutEffect`，paint 前）再按视野量。`TAIL_N`/`tailRef` 退役。
- ⚠️**十轮的「钉底兜位移」又错 → 十一轮改锚点滚动补偿 `withAnchor`**：十轮在退出/悬停时强制
  `scrollTop=scrollHeight` 来兜住内容高度变化，本身就是用户报的「退出被拽底」「悬停被拽底」；而瞬藏屏外行
  留给 rAF 下一帧改、不补偿滚动，则是「开始淡出时跳一格」。**修法——一切批量显示/隐藏都走 `withAnchor(fn)`**：
  改前记住视野内**最下**一条可见行的 `getBoundingClientRect().top`（淡出从上往下走，底部最稳），fn 改完后
  `scrollTop += (新top−旧top)` 复位——眼前内容纹丝不动，绝不强制钉底。落点：①悬停 `onEnter` 揭示全部（补偿，
  上方撑高不再拽视野）；②`leaseVisible` 屏外行**当场** `display:none`（补偿，不留给 rAF 下帧跳）；③rAF 内自然
  淡完的行攒成 `toHide` 一次隐——贴底时钉底自然抵消、未贴底时走补偿；④退出聊天**保持用户当前滚动位置**，
  `stickRef` 按现位置重测（`距底<40px`），淡出从他正看着的视野起。
- **不拽底**：唯一钉底在 rAF `if (stick && !frozen)`；`onScroll` 据「距底 <40px」维护 `stickRef`。滚上去
  读史 → `stick=false` → 撤离/恢复都**不钉底**（#1 根治）。底部锚定改**内层 `.mc-chat-log-inner`
  `margin-top:auto`**（比 `:first-child` 稳——逐条 `display:none` 会让首行 margin 失效）。
- 验证（帧钟需真机 rAF；headless 会节流/暂停 rAF 与 setInterval，故 Node 侧手动步进 `__step` 驱动帧确定性
  核对）：全历史 21 行全渲染、464px 内容在 220px 框内可滚且滚顶保持、悬停满显 21 行全不透明、离开+过宽限
  scrollTop 不被拽底；淡出算式经 born/activeRef 探针核对精确（remain 968→opacity 0.65）、`display:none` 回流、
  悬停冻结不再续淡、贴底 rAF 钉底 186/186。真机 rAF 由 r3f 场景 60fps 保活，帧钟=墙钟。
  十一轮追加（可见行屏幕位置逐条比对）：展开滚顶→Esc 后 `scrollTop` 保持 0、视野=最早片段且从该片段起淡；
  贴底关闭瞬间可见行最大位移 0px（一格≈26px）；淡出中悬停前后最大位移 0px 且上方揭示出更多历史。
